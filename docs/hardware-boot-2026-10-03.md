# Switch hardware boot observation — 2026-10-03

Evidence: user-supplied `/home/tester/Pictures/switch2.jpg`, following build 3
SD power recovery and the screen console update.

The photo shows these stages and messages:

- Kernel device initialization and `uart0: console (115200,n,8,1)`.
- `Trying to mount root from ufs:/dev/md0 [rw]...` and the preloaded root image.
- `Dual Console: Video Primary, Serial Secondary`.
- `start_init: trying /sbin/init`.
- `SWITCHBSD: USERLAND_READY`.
- `FreeBSD freebsd-switch 15.1-RELEASE FreeBSD 15.1-RELEASE SWITCHDIAG arm64`.
- `hw.machine: arm64`, `hw.model: ARM Cortex-A57 r1p1`, `kern.smp.active: 0`.
- The RAM-root notice, diagnostic-shell notice and `#` prompt with a block cursor.

This confirms kernel execution, RAM-root startup, userland execution and shell
startup on the Switch display. The uname and sysctl output is generated by
`config/rc`; it does not demonstrate interactive input. A still photo also
does not establish sustained stability. RTC/time and PMU warnings are visible
but did not prevent this boot from reaching the shell.

The supplied local artifacts are preserved under
`build/hardware-userland-2026-10-03/`, including firmware, loader configuration,
both update ZIPs, the full SD ZIP and distribution metadata/checksums. The
`observation.json` file records the photo SHA-256. No files were read back from
the physical SD card, so local artifact hashes are provenance for the supplied
build, not independent verification of the card's contents. Distribution files
were not rebuilt solely for this documentation update; their metadata predates
this hardware observation.

the screen-primary default is `NO`. Consult `boot-test.md` before connecting a
serial adapter. Builds 4–6 attempted firmware USB-host input but produced a
black screen before UEFI on the latest test. Build 7 disables that experimental
